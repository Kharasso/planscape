# 1. Data Source

## 1.1 RPLAN (floor plan images and human annotations)
A large-scale, real-world residential floor-plan dataset that provides raster/vector representations with rich semantic labels (e.g., room types, boundaries, and connectivity). It is designed to support floor-plan analysis and generation tasks and includes per-room annotations and layered renderings enabling both pixel-level and object-level reasoning. (Source: https://wutomwu.github.io/particulars.html?id=1)

## 1.2 NeuLab/VisualPuzzles (transfer task)
A multimodal benchmark of diagrammatic puzzles aimed at testing visual reasoning with minimal domain knowledge. It spans several categories—Algorithmic, Analogical, Deductive, Inductive, and Spatial—with varying difficulty levels and VQA-style (image+text) formats. (Source: https://huggingface.co/datasets/neulab/VisualPuzzles)

## 1.3 SPARE3D (transfer task)
A spatial reasoning dataset built around three-view (orthographic) line drawings of mechanical parts. It supports multiple 2D↔3D reasoning tasks (e.g., view consistency, camera pose understanding, and 3D shape reasoning) and is commonly used for evaluating multi-view geometric understanding. (Source: https://github.com/ai4ce/SPARE3D)


# 2. Preprocessing

## 2.1 Reorientation of floor plans based on entrance orientation
All floor plans are reoriented so that **the entrance opens to the living room and faces upward** in the drawing. We detect the entrance and interior of the unit, getting a vector pointing from the entrance inward to the unit, and rotate the plan so that this vector aligns with the positive **y** axis. This establishes a consistent "up" direction.

## 2.2 Feature Engineering

### 2.2.1 Functional features
Construct features based on area, room type, the x and y coordinates of room centroids, pairs of rooms of different types, the area ratio of the pairs, the x and y coordinates of the centroids of the pairs, triplets of rooms of different types, the area ratio of the triplets, and the x and y coordinates of the centroids of the triplets.

### 2.2.2 Shape features
Image-based features — three channels:

1. Footprint of the floor plan
2. Footprint of the living room
3. Footprint of the entrance


# 3. Clustering

We experimented with **spectral clustering** and **K-Means** over standardized features (zero-mean, unit-variance) with **data whitening**. Based on silhouette scores, Calinski–Harabasz statistics, and elbow-method inspections, we chose **K-Means** for stability and scalability. The selected **k** for functional features is **20**, while shape features use **30** clusters.

## 3.1 K-Means clustering on functional features
Ranking of important features in each cluster based on information gain (tree-based methods).

## 3.2 K-Means clustering on shape features
K-Means on the three-channel shape features (plan footprint, living-room footprint, entrance footprint), yielding **30 clusters**.

# 4. Odd One Out Task

## 4.1 Baseline models
[Baselines](https://docs.google.com/spreadsheets/d/1NnBN4BEcfumsMIC3xgqkyB-dfjLOSPtZiWiY9oPl4J4/edit?usp=sharing)

### 4.1.1 Textual prompt using human annotations
The evaluation is performed on the 5,000 plans with human annotations (the other 75,000 annotations are generated by an LLM).  
**Models:** Gemma 2-9B-IT; Llama 3-8B-IT

### 4.1.2 Image prompt
Constructing an image with five options and letting the model pick the odd one out.  
**Models:** Qwen 2.5-VL; Phi-4 Multimodal

### 4.1.3 Two modalities — image + human annotations
Combining the human annotations and the image used in 4.1.1 and 4.1.2 in the input.  
**Models:** Qwen 2.5-VL; Phi-4 Multimodal

**Notes:** For the images, we tested putting a box around the options, including a legend in the image, and including a verbal description of what color denotes which room type. We evaluated whether the floor plan is the original plan or is reoriented.

**Two versions of tasks:**
- **a.** The odd one has a different functional cluster and a different shape cluster from the others.  
- **b.** The odd one has a different functional cluster from the others but the same shape cluster as the others.

## 4.2 Human evaluation

We run blinded human judgments (≥3 raters/item) on samples from tasks **a** and **b** to assess: (i) agreement with the intended odd-one rationale, (ii) prompt clarity across modalities, and (iii) inter-rater agreement (e.g., Fleiss’ κ). Disagreements are cataloged to refine instructions and legends.
